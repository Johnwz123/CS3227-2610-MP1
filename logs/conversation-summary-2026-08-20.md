## 5. BudgetBot application requirements and implementation

The starter application was replaced with BudgetBot, a local JavaFX desktop
budget tracker for one user. The agreed product behavior was:

- Local SQLite persistence with no account, cloud synchronization, bank feed,
  or external service.
- Sensible default expense categories, including Housing & Utilities,
  Groceries, Dining, Transport, Health, Entertainment, Shopping, Education,
  and Miscellaneous.
- Add, rename, and remove categories. Removing a referenced category requires
  reassignment to a replacement category.
- Income and expense transactions. Income affects cash flow but is not
  assigned to a category; expenses require a category and contribute to that
  category's monthly spending.
- Fixed monthly category budgets and configurable warning thresholds.
- A dashboard showing budget progress and warning/over-budget states.

The initial model included an opt-in global rollover setting. A later
dashboard-simplification change removed rollover and carryover entirely:
monthly availability is now always the fixed base amount, and historical
monthly snapshots retain their own warning threshold and base amount.

The implementation is layered:

JavaFX UI -> BudgetService -> BudgetDatabase/repositories -> SQLite

BigDecimal is used for monetary values. BudgetService validates positive
transaction amounts, non-negative budgets, two-decimal precision, dates,
transaction types, categories, warning thresholds, and filter bounds before
delegating to persistence.

## 7. UI refactor and package organization

The user identified BudgetBotWindow.java as a god file and asked whether it
should be refactored. The window was split into a shell, coordinator, views,
dialogs, table factories, alerts, and money-input helpers.

The files were then organized under this package structure:

budgetbot.ui

- BudgetBotWindow: stage, shell, and navigation.
- ViewCoordinator: selected month, active view, and rerendering.
- MoneyInput: money parsing and formatting.
- UiAlerts: confirmation, information, and error dialogs.
- views/: dashboard, transactions, budgets, settings, and month controls.
- dialogs/: transaction, category, and budget dialogs.
- tables/: transaction and budget-summary table factories.

Tests were moved and updated with the package structure. The selected month is
preserved when the user navigates between views, and each month-aware view
refreshes itself instead of forcing navigation back to the dashboard. Table
cell styles use semantic classes for income, expenses, normal remaining
amounts, warnings, and over-budget states.

When asked to identify other god files, the persistence layer was identified as
the next major extraction target.

## 8. BudgetDatabase extraction into focused repositories

The user approved refactoring BudgetDatabase and extracting focused
repositories while adding or updating tests.

The former large database class was reduced to a connection-owning facade.
Responsibilities were moved into:

- CategoryRepository: category listing, addition, renaming, and transactional
  reassignment/removal.
- SettingsRepository: global settings load/save.
- TransactionRepository: transaction CRUD, filtered retrieval, expense totals,
  net cash flow, and balance calculations.
- MonthlyBudgetRepository: monthly snapshot creation and base-amount updates.
- SchemaInitializer: repeatable SQLite table creation and default-category
  initialization.
- PersistenceSupport: shared conversion of JDBC failures into
  BudgetPersistenceException.

The public BudgetDatabase API remains stable for service and UI callers. A
nullable-category mapping defect found during testing was corrected by checking
ResultSet.wasNull() immediately after reading the category column. A reopening
test verifies that existing categories and settings survive a second database
open without duplicate seeding.

The persistence refactor was later extended for transaction queries and the
selected-month net-cash-flow model.

## 10. Repository-tracked follow-up changes

After the original MVP archive, the repository contains these additional
archived OpenSpec changes. They are included because they represent later
development work in the same application.

### Database reset and demo-data tooling — 2026-08-21

The project gained safe, repeatable database tooling:

- DatabasePaths resolves the default ~/.budgetbot/budgetbot.db path and
  normalized explicit paths.
- DatabaseTool supports reset and deterministic seed operations.
- PowerShell and POSIX launchers call the Gradle/Java tool.
- Reset requires literal RESET confirmation or an explicit force option,
  removes only the selected database and matching SQLite sidecars, and then
  recreates the normal schema.
- Seed creates fixed current-month categories, budgets, income, and expenses.
- Seeding refuses to duplicate a database that already contains transactions.
- Tests cover path resolution, destructive-operation safeguards, sidecar
  cleanup, deterministic data, duplicate-seed refusal, and dashboard cash flow.

### Native desktop packaging and releases — 2026-08-21

Native packaging was added using JDK 25 jpackage/jlink support:

- packageAppImage creates a self-contained application image.
- packageNative creates the host-native installer under build/packages/.
- Supported artifacts are Windows .msi, macOS .dmg, and Debian/Ubuntu .deb.
- A full JDK with jpackage is required; WiX is required for Windows MSI
  creation.
- The release workflow triggers only for tags matching
  v<major>.<minor>.<patch>.
- Windows, macOS, and Ubuntu packaging runs in a matrix after quality checks.
- A dependent publish job creates or updates one GitHub Release only after all
  platform artifacts succeed.
- Installed application files remain separate from
  ~/.budgetbot/budgetbot.db, so normal uninstall preserves user history.
- Packages are currently unsigned and may produce platform trust warnings.
- A macOS version-normalization fix handles 0.x.y release versions.

### Simplified monthly dashboard — 2026-08-21

The dashboard model was simplified:

- Lifetime Overall balance became selected-month Net cash flow.
- The global Recent activity section was removed so dashboard content is
  selected-month scoped.
- Global rollover and monthly carryover were removed.
- Every category starts each month with its fixed base amount.
- Settings retain the warning-threshold feature.
- Models, persistence schema, service calculations, UI, tests, and guides were
  updated. The unreleased simplified schema intentionally has no migration
  compatibility for earlier development databases.

### Transaction search and filters — 2026-08-23

Transaction history gained a query model and composable filters:

- Description search is case-insensitive.
- Date ranges are inclusive and may be one-sided or cross-month.
- Category, income/expense type, minimum amount, and maximum amount filters
  can be combined with AND semantics.
- Blank descriptions normalize to no search criterion.
- Reversed dates and amounts outside valid bounds are rejected without changing
  stored data.
- The selected month remains the default date range only when explicit date
  bounds are absent.
- The UI has Apply and Clear actions, result counts, no-results feedback, and
  mutation refreshes that preserve the last successful query.
- Income selection clears and hides the expense-category filter; choosing a
  category selects Expense.
- Responsive grouped controls keep related filters legible as the window
  narrows.
- Transaction and budget validation messages wrap in finite-width TextFlow
  regions, and dialogs resize after validation so Save and Cancel remain
  visible.
- Repository, service, and JavaFX tests cover independent criteria, combined
  criteria, inclusive bounds, invalid ranges, empty states, clearing, and
  mutation refreshes.

### Quality-tool and dependency maintenance

Repository history also records later quality-tool and dependency work:

- ArchUnit package-layer and cycle tests were added.
- SpotBugs with FindSecBugs was added with a reviewed exclusion filter for
  narrowly scoped UI/service constructor false positives.
- Action, Gradle, SQLite, JUnit, Mockito, Spotless, and Hamcrest versions were
  updated through maintenance changes.
- The CI and release workflows retain least-privilege permissions and Linux
  wrapper-executable handling.

database tools, native packaging, Docusaurus documentation, CI, Pages
deployment, and tag-based release publishing.

Important user-facing commands documented in README.md include:

- gradlew.bat run
- gradlew.bat check
